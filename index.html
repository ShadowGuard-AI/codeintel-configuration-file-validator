Validated Against a Schema

codeintel-configuration-file-validator validates configuration files, JSON or YAML, against a JSON Schema. It identifies missing required fields and incorrect data types against the schema. It uses jsonschema, named here in the same plain way the README names it.

One Built In Check Only

Or it runs the one built in best practice check: the top level api_key must not be left at its default placeholder value.

A Placeholder Api Key Exits 1

A failure of that check exits 1.

Usage, the Placeholder Shown for What It Is

./codeintel-configuration-file-validator [params]

The README Names No Configuration File

The README prints that line as its whole usage line, and its parameter list also names no configuration file argument at all, listing only options, so a reader following the README alone would not know what file to hand the validator. No fuller invocation is invented on this page.

Parameters, Four Entries and No More

-hShows a help message and exits.
--schema_fileGives the path to the JSON schema file. If not provided, the tool only checks that the configuration file parses, unless --best_practice is given.
--formatSpecifies the format of the configuration file. If not given, it will be inferred from the file extension.
--best_practiceRuns the one best practice check: the top level api_key must not be left at its default placeholder value, and a failure exits 1. This is the one check the tool carries built in.

Without a Schema, Only Parsing Is Checked

The absence of a schema changes what a run means, and this page records that condition in full.

What a Run Can and Cannot Settle

Parses Is Not Validated

With a schema, missing required fields and incorrect data types are identified against that schema. Without a schema and without --best_practice, a run settles only that the file parses, and this page does not dress that up as validation. With --best_practice and no schema, the one built in rule is the whole judgement. No drift is watched, no live system is visited, and no file is repaired. A file is checked as it stands, once, and reported.
